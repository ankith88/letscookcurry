# Plan 01-01: Site Settings Store, Admin Allowlist & Global Ordering Mode Controls

## Objective
Implement the Firestore-backed `SiteSettings` system (`settings/site`), admin email allowlist verification, real-time `SiteSettingsProvider`, and conditional UI rendering across the entire website so that:
1. Turning **Ordering Process Inactive** (`orderingFeatureEnabled: false`) hides all ordering sections, schedules, cart buttons, prices, and order history — transforming the site into a clean recipe-showcase website.
2. Turning **Ordering Process Active** (`orderingFeatureEnabled: true`) restores all ordering sections and respects the Admin **Orders On/Off/Auto** control (`orderWindowMode: 'open' | 'closed' | 'auto'`).

  <files>
    - src/lib/types.ts

  <action>
    1. In `src/lib/types.ts`, add `OrderWindowMode = 'auto' | 'open' | 'closed'` and `SiteSettings` interface (`orderingFeatureEnabled: boolean`, `orderWindowMode: OrderWindowMode`, `adminEmails: string[]`, `updatedAt?: string`, `updatedBy?: string`).
    2. Create `src/lib/settings.ts` with:
       - `DEFAULT_SITE_SETTINGS`: `{ orderingFeatureEnabled: true, orderWindowMode: 'auto', adminEmails: [] }`
       - `getSiteSettings()`: Reads `doc(db, 'settings', 'site')` with safe fallback to `DEFAULT_SITE_SETTINGS`.
       - `updateSiteSettings(partial: Partial<SiteSettings>, updatedBy?: string)`: Merges updates into `doc(db, 'settings', 'site')`.
       - `computeIsOrdersOpen(settings: SiteSettings, date?: Date)`:
         - If `!settings.orderingFeatureEnabled`, returns `false`.
         - If `settings.orderWindowMode === 'open'`, returns `true`.
         - If `settings.orderWindowMode === 'closed'`, returns `false`.
         - If `settings.orderWindowMode === 'auto'`, returns `day >= 1 && day <= 4` (Monday–Thursday).
    3. Create `src/lib/admin.ts` with `isAdminUser(email?: string | null, settings?: SiteSettings)`:
       - Parses `process.env.NEXT_PUBLIC_ADMIN_EMAILS` (comma-separated, case-insensitive) + `settings?.adminEmails`.
       - If no admin emails are configured yet in env or Firestore, allows bootstrapping by the first signed-in user on `/admin` (with a one-click "Claim Admin Access" or email match) so the owner is never locked out during initial setup.
  </action>

</task>
